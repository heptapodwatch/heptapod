# Contract boundary

Import core only through `Heptapod\Contracts`; framework and installed package imports are allowed. Never import core models, execution, recording, incidents, events or history implementations. Never reach around the history or persistence seams with direct core-table queries.

- A check type may implement `ReportsAvailability::availability()` and return `CheckAvailability` with a nullable reason translation key. Null means available; other check types are implicitly available. This deployment capability is not an observation. Core excludes unavailable types from claims and queued execution; UI/API present the reason without changing the last run result or emitting an incident/notification.
- `CheckType::definition()` returns `CheckDefinition`: key, UI label key, Lucide icon id, queue, timeout, interval, failure threshold, execution mode, config/metric schemas, emitted event names and `requiresHttps` (default false). The UI uses definition-supplied label/icon metadata. Addon `<type>.label` translations remain for Oh Dear API label parity (for example `certificate_health.label` is "Certificate health", while the UI label is "Certificate"). Certificate-health and mixed-content declare true in their own definitions; core does not infer addon semantics from keys. The core `CheckEnablement` boundary rejects HTTPS-required checks for HTTP sites. Add-site/enable API/UI flows must use that boundary and hide inapplicable checks. Keep the addon's `not_https` failed-observation runtime guard for later URL edits.
- Queue is `checks-fast`, `checks-crawl` or `checks-browser`. The engine owns queue-wait, lease, retry and Horizon budgets.
- `CheckContext` carries site/check/reserved-run IDs, claim token, URL, start/deadline, validated decrypted config, ordered decrypted `crawlerHeaders` (name/value pairs), immutable previous result and optional history reader. Its JSON/debug representation omits both config and crawler headers. Never log execution inputs. The execution engine constructs crawler headers explicitly from the site's encrypted storage; addons must not import site models.
- `CheckOutcome` has a non-pending `RunResult`, summary translation key and params, a concrete laravel-data metrics DTO, bounded evidence and structured `AddonEvent`s. Null means no observation; it must not alter the streak or incident.
- Addon events carry type, dedupe key, positive payload version, secret-free payload and optional `SuppressionSubject`. A null subject means the current whole check. Cron tasks and application-health components set their typed positive component ID; the recorder rejects a subject for a different check. Their identity must distinguish meaningful same-severity changes and accepted runs.
- Check detail snapshots extend `CheckDetailData` and initialize its `check_type` discriminator. Register the DTO class in `CheckDefinition::detailDataClass` and implement `CheckDetailProvider::detail(int $checkId, ?LatestRunEvidence $latestRun = null)` on the registered check type. Core authorizes the check before calling this read seam and supplies its latest retained accepted run's physical reference, result and bounded evidence. Comparison baselines are not current observations; use run evidence for current detail when baseline publication can be withheld. Return null only when no accepted observation exists; storage errors propagate. Detail fields must be bounded and secret-free. Core imports only the contract, never addon DTOs. The TypeScript transformer generates the discriminated union from the installed registry; do not maintain a second list of implementations.
- `HistoryReader::read()` selects accepted observations for site/type over `[from, until)`, ascending ended_at/id, bounded by a limit in 1..10000. Empty history is legitimate; storage errors must propagate.
- `RunReference` contains both integer ID and immutable ended_at. Shared sequence allocation is not a global database uniqueness constraint.
- Addons that execute system binaries declare their binary names in `addons/<name>/composer.json` under `extra.heptapod.system-requirements` (for example, `["dig"]` for DNS). Install the providing OS packages in both app Dockerfiles; an omitted declaration means the addon needs no system binaries. Test-only tools are not production requirements.

`ChromiumRenderer::lighthouse(url, context, options)` returns the raw LHR payload in `LighthouseReport` and serves only Lighthouse. Broken-links, mixed-content and sitemap checks use plain HTTP with spatie/crawler; there is no JavaScript-rendered crawl. PDF reports use spatie/laravel-pdf with Gotenberg outside this seam. Browserless is not part of the product.

Addon-internal coordination (for example, crawl freshness) may read another enabled check's settings through `SiteCheckSettingsReader::read(siteId, CheckKey)`. The readonly result exposes `enabled` and execution-only decrypted `config`; JSON/debug output omits config. Do not use it to read another addon's results or query core tables.

## Outbound HTTP

`DomainRegistrationLookup::fetch(string $domain, CheckContext $context)` receives the execution context so RDAP and IANA bootstrap requests share the engine deadline. Its shared fake matches the domain; HTTP request policy and deadline propagation are verified through `FakeOutboundHttp`. WHOIS remains bounded native TCP, never HTTP-WHOIS.

Every external HTTP fetch MUST use constructor-injected `Heptapod\Contracts\Http\OutboundHttp`. Do not import Laravel Http or Guzzle in addon source. For libraries such as spatie/crawler, pass `clientConfig($request, $context)` as their Guzzle client options. Keep the returned handler intact; per-request options cannot disable its bounds, TLS or redirect policy. Library options may enable `allow_redirects.track_redirects: true` to retain final-URL/history metadata; the seam still owns hop limits, protocols and per-hop guard/pinning. Transport failures throw only `FetchException` with its typed `FetchFailure` in library integrations. Unexpected programming/runtime errors still propagate.

```php
use Heptapod\Contracts\Http\FetchRequest;
use Heptapod\Contracts\Http\RedirectPolicy;

$result = $this->http->fetch(new FetchRequest(
    $endpoint,
    headers: $headers,
    maxWireBytes: 1024 * 1024,
    maxDecodedBytes: 1024 * 1024,
    redirects: RedirectPolicy::Off,
    acceptedStatuses: [200, 401], // Omit/null for the default 2xx set.
), $context);
```

`OutboundHttp::pacedClient($context, $additionalDelayMilliseconds)` returns an execution-scoped `PacedHttpClient` for sitemap probes. Its `fetch(FetchRequest): ?FetchResult` and keyed `fetchMany(array): array` share a per-host limit of four and a nominal 110 ms plus additional-delay start gate across documents, batches and redirect hops. A null result means not checked because admission was refused or a timeout was clamped to the check budget; never turn it into a broken-link finding. Unexpected errors propagate. The request ceiling begins at first admission and does not reset on redirects. The core implementation retains the guarded transport and uses the supported `select_timeout` constructor option only for this paced session; ordinary `fetch` and `clientConfig` callers retain their defaults. No environment knob or addon-side Guzzle import is required. Bind the existing `FakeOutboundHttp` seam for addon behavior tests; real pacing/security traces remain core-owned.

- `FetchRequest`: URL, method (default GET), ordered duplicate header values, optional raw body, positive wire/decoded entity-byte limits (each default 1 MiB), redirect policy, hop limit (default 5), optional site host, optional positive timeout ceiling, and optional explicit integer `acceptedStatuses` (null defaults to 2xx). Non-integer elements, including numeric strings/floats, throw a configuration exception. There is no insecure TLS option. Each initial library dispatch starts its own `timeoutSeconds` ceiling, bounded by the remaining context deadline. That request deadline bounds connect/total time across all of its redirect hops; constructing or reusing a library client does not start or reset the overall check budget. Less than 1 ms remaining is a typed timeout. Library scheduling `delay` and callbacks `on_headers`, `progress`, `on_trailers` are unsupported and fail loudly with fixed configuration diagnostics; `on_stats` remains supported and unexpected callback errors propagate. Templates are header-validated before clientConfig returns; library callers must not add unvalidated configuration headers during Guzzle's pre-handler construction. Caller-supplied FetchRequest `Host` headers are forbidden; the URL sets Host. At library dispatch, Host must be exactly one value equal to the URL authority; overrides and duplicates fail validation. Outbound HTTP DNS lookups share the request deadline through the native resolver's bounded subprocess; the engine job timeout remains the execution backstop.
- `RedirectPolicy::Off`: no redirects, but initial-target validation still applies. `Operator`: private addresses are allowed only for the configured URL's normalized host and only from its first resolution in this execution. Every cross-host redirect requires public addresses; there is no private-target override. `Untrusted`: crawler-discovered/sitemap-listed URLs, guard validation and re-pinning on every dispatch and redirect; supply the operator's `siteHost`. Same-host means equal lowercased, IDNA-normalized hostname strings with trailing dots removed, not equal resolved IPs. Each distinct hostname is resolved once per execution; all later dispatches and redirects use that same numeric set. DNS changes cannot introduce new private destinations. Known provider metadata endpoints, link-local addresses and IPv4 translation/tunnel prefixes are always refused, including on initial targets. DNS classification and native cURL pinning use the same cached resolution; the redirect callback does not perform a second lookup. NAT64 and 6to4 destinations are refused even for the configured hostname. A server on an IPv6-only network that reaches IPv4 sites through DNS64/NAT64 is not supported. Plain RFC1918 and IPv6 ULA intranet targets retain the first-resolution exception. `maxRedirects: 0` disables hops while retaining untrusted initial-target validation. Untrusted library dispatches use the normalised site origin from `CheckContext.url`, not the discovered URL's origin. Every initial dispatch and redirect outside that origin removes all caller/default-supplied headers, even Accept/User-Agent. Operator redirects remove those headers on cross-origin hops. The seam generates a new Host and the `HeptapodBot/<version> (+https://heptapod.watch/bot)` User-Agent; native cURL can generate Accept-Encoding. Stripping persists through the redirect chain, including A → B → A. Header names never establish secret safety.
- TLS always uses native cURL verification and system roots, or the operator PEM configured through `certificate_health.ca_file`. CA configuration errors fail loudly.
- `FetchResult`: nullable HTTP status, bounded body and response headers, nullable failure, and dispatch-ordered cURL `transfers`. Numeric timing values (`namelookup_time`, `connect_time`, `appconnect_time`, `starttransfer_time`, `pretransfer_time`, `redirect_time`, `total_time`, `header_size`, `size_download`, `speed_download`) retain native units. The child's monotonic `socket_addrinfo_lookup` duration is added to native `namelookup_time` and cumulative timing markers, including `total_time`. PHP process startup and parent communication are excluded from site timing metrics; a cached guard lookup adds zero. HTTP without TLS and reused connections retain zero handshake markers. Requests with no response invent no timing sample. No request URLs or raw handler metadata appear in timing output. Advertised Content-Length applies only to responses with bodies, using the actual dispatched method: HEAD and 1xx/204/304 do not count representation lengths as downloads. Actual wire downloads and decoded-byte limits remain enforced, including accepted non-2xx bodies.
Policy refusals (`private_target` and `redirect_blocked`) are execution-only signals in `CheckContext.policyRefusals`. The executor owns their classification as Check error with null metrics, a typed cause and no availability/outage grouping. Addons may retain bounded evidence, but cannot turn a refusal into downtime or a failed finding. Exception: an `Untrusted` request for a discovered target (a crawled link or resource, a child sitemap or listed URL) sets `FetchRequest.refusalIsFinding`; the guard still refuses it, but the refusal is not recorded and the addon reports it as a per-item finding, so the rest of the run counts. Operator targets and start pages never set it. Numeric diagnostic addresses contain no URL, path, credential or body. Trust is not persisted.

- `FetchFailure`: kind `timeout|too_large|tls|dns|connect|redirect_blocked|too_many_redirects|private_target|http_status|invalid_request`, known HTTP status, short vendor exception class when applicable, and static bounded `detail()`. It retains no vendor exception/message/body/URL. Statuses outside the caller's accepted set are `http_status`; transport errors also fail. Failures never carry bodies or response headers, including library responses. There is no error-payload redaction path and no extra `secrets` request argument. Accepted success bodies belong to the caller: they remain bounded/decoded but untouched, including accepted 401/3xx bodies. Callers must redact every persisted/displayed key and value themselves. Invalid request construction and header validation produce sanitized `invalid_request`; unrelated runtime errors propagate. Header prevalidation failures carry nullable structured `headerName`, `headerPosition`, `headerValuePosition` through FetchResult.failure and FetchException.failure. Positions are zero-based ordinals in the validated configuration array or dispatched PSR headers (which can include generated headers). Value position is null for invalid names/disallowed Host headers or empty value lists (no value exists). Names are bounded to 128 bytes after non-printable/non-ASCII bytes are escaped with native addcslashes; values and vendor exceptions are never retained. The human diagnostic remains a fixed reason code.
- `FakeOutboundHttp::respondWith($request, $result)` matches the entire request, records request/context pairs in `requests`, and throws on unexpected requests. Configure library requests with their actual PSR-generated headers/body. Bind the fake before resolving the check. Do not fake parsers or recorder/domain collaborators.

Uptime uses Operator redirects with `strictRedirects: false` (POST becomes GET without a body on same-origin 301/302; 307/308 preserve the method/body) and caps wire and decoded response bodies at 10 MiB by default (`heptapod.uptime.max_response_bytes`, configured through `UPTIME_MAX_RESPONSE_BYTES`). `look_for_string`, `absent_string` and JSON body assertions read only responses within that cap; oversized responses fail before evaluation, without partial/truncated assertions. JSON body assertions retain a separate fixed 2 MiB evaluation limit. Other callers default to strict redirects. Cross-origin body redirects are blocked against the original request before any method/body rewrite. Bodies exceeding either cap produce failed observations with `response_too_large` and a translated limit diagnostic; configured status/body/header assertions and timing semantics are preserved. `FetchResult.effectiveUrl` is success-only and excluded from debug output; never persist/log it raw (queries can contain secrets). Cross-origin redirects with a request body are blocked before dispatch, including 303 redirects.

Execution modes:

| Mode    | Consumer                                                            | Behavior                                                                 |
| ------- | ------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| poll    | uptime, certificates, DNS, domain, health, Lighthouse, crawl checks | Collect observations                                                     |
| push    | cron                                                                | Evaluate ping deadlines; pings do not pretend to be HTTP probes          |
| derived | performance                                                         | Read uptime observations over the previous 15 minutes; no second request |

`Schema` and `Field` support strict scalar types, nested objects, ordered lists and secret string leaves. Closed objects reject unknown fields. Only explicitly open objects preserve extras (Lighthouse notification settings). Objects reject numeric-keyed lists; empty schema objects serialize as `{}`, while lists remain `[]`. Execution config reconstructs associative arrays. `Field::default` declares an optional addon-owned runtime/import default; the Laravel Data `Optional` sentinel distinguishes no default from an explicit null default. `Schema::defaults()` exposes only declared defaults. `Field::uppercase` normalizes declared non-secret string fields recursively before validation; wrong types are not coerced, and secret fields cannot opt in. Runtime evaluation reads the same defaults; schema validation and partial API writes never insert them implicitly. Required fields, especially secrets, have no defaults. `Field::trimmedStrings` opts a `List<String>` into trimming and dropping blank entries before validation, shared by API/UI/import configuration writes. Other field/item types fail construction; wrong item types and associative list shapes remain invalid. `FieldPresentation` contains translated labels/help/options, not validation rules. Use Laravel validation rules for bounds, enums, nullable fields and limits such as ten body assertions.

Call `Schema::validateConfig()` before assigning a check's config. The resulting `ValidatedConfig` serializes only redacted public leaves. Scheduling and `failed_notification_threshold` must not be fields in persisted config: extract them at the configuration boundary into `interval_seconds` and `failure_threshold`, then project them on the wire. Partial request omission does not reset settings.

Result values: `succeeded`, `warning`, `failed`, `errored-or-timed-out`; `pending` exists only on check snapshots. Warnings count as online. Operational pause, disable, snooze and maintenance are not results. Run and summary DTOs map engine errors to `failed` for Oh Dear; check DTOs preserve the internal value.

The fixed outcome envelope is typed by `CheckOutcome`; do not duplicate its schema. `metricSchema` describes the concrete metrics DTO. The recorder calls `metricSchema->validateValues($outcome->metrics->toArray())` before acceptance. Validation mismatches are observable errored runs, not silent drops. Evidence is an optional concrete laravel-data DTO with bounded, secret-free fields.

Metrics may be null only for `errored-or-timed-out`; all other outcomes require a concrete metrics DTO. Errored outcomes require `CheckError` (exception class/message, redacted at the engine boundary). Record diagnostics in the run's `error` column. An engine exception is not target downtime. Null metrics are not empty or zero samples: metric reads and rollups must explicitly skip them, while result counts still include errored runs.

Define meaningful same-severity events per addon: DNS record diff; certificate fingerprint change; newly broken URL or mixed-content finding; sitemap issue-set change; newly missed cron task; health component status/message change; domain registration/expiry change; Lighthouse threshold crossing. Uptime and derived performance emit result transitions only. Declare each event in `emittedEvents`, dedupe by accepted change identity, and include the component suppression subject for cron/health. Do not emit unchanged findings on every poll. Certificate health emits `certificate_health.certificate_changed` against the retained accepted fingerprint, not the immediately preceding errored run or an unaccepted attempt. Its versioned payload contains old/new fingerprint, issuer and `valid_to`, never PEM or secrets. First observation and unchanged fingerprints emit nothing. Identify a replacement by the accepted predecessor run and new fingerprint, so a later A → B → A → B remains a new accepted change.

Notification routing discovers literal addon events through `emittedEvents`. An addon can map its own events (or `check.warning`) to a product routing key by calling `mergeConfigFrom(__DIR__.'/../config/notifications.php', 'notifications.event_types.<check key>')` in its provider. Each entry is a routing-key string, or a result-value → routing-key array for component events; their payload `result` takes precedence over the parent's aggregate result. Unmapped declared events retain their literal key and severity from the event result. Core must not list addon event names. Component notifications carry `component_name`, `failure_started_at` and `recovered_at` in their versioned payload. Keep the component failure baseline only when an attempt is accepted; preserve it through repeated failures and retention, then clear it on successful/warning acceptance. Core renders component identity and component downtime independently of the aggregate incident. Legacy payloads without component timestamps omit downtime rather than borrowing an aggregate timestamp. Uptime/performance use core result/incident routing; certificate-health maps warnings to `certificate.expiring`; cron maps failed task changes to `scheduled_task.missed`.

History is optional: addons not reading observations can construct a context without it. Performance requires it and fails loudly when missing. Addon constructors receive external seam interfaces; never resolve dependencies with app() inside an addon.

## Import monitors from an Oh Dear account

Register an optional `OhDearImportMapping` as the second argument to `CheckRegistry::register`. Its `settings` list is the exact Oh Dear setting-key allowlist; core reports every unmapped type or field as not yet supported, skipped. Config stays validated by the addon's existing `configSchema` and written through `UpdateSite`/`UpdateCheckConfig`. Missing required root config is reported as setup-required without creating a check; malformed values and incomplete nested objects report all fields per check. Valid checks and the site still import; any invalid check makes the command exit nonzero. Missing/null optional config uses declared field defaults on every import, including reruns; API omission still preserves existing settings. Remote locations are excluded because one local probe cannot honor them.

An addon with task definitions may supply the class-string of an `OhDearDefinitionImporter` in the mapping. `validate(definitions)` shares the same validator as creation and performs no writes; `__invoke(checkId, definitions)` is the addon-owned import action. Definitions carry source integer `id` plus editable attributes, never source ping credentials or runtime results. Persist a nullable unique `oh_dear_id` in addon-owned storage, update mapped definitions in place, and reuse the existing creation action for new definitions. Missing source definitions are retained: account import is not destructive API synchronization. The cron importer preserves local UUIDs so operators can migrate their ping URLs once.

## Push evaluation and components

Cron still runs through dispatcher claims, engine execution and recorder fencing. Addon-owned task definitions have their own typed fields and validation, not parent configSchema. Task frequency is not the parent evaluator's interval_seconds. Preserve request omission and stored NULL on the wire. Cron's nullable grace uses the addon-config default (5 minutes), explicit zero stays zero, and invalid defaults fail loudly; load it with mergeConfigFrom.

Starting a task is not success. During grace retain the preceding state; at due+grace fail unfinished work. Late finish inside grace warns; an on-time or post-expiry finish succeeds and retains lateness evidence. Coalesce missed deadlines. An absence of observation is not a fabricated pass. Health's empty/skipped-component policy is not inferred from cron: an empty `checkResults` collection with a valid `finishedAt` succeeds and retains the EN/DE informational `application_health.no_checks` summary, without a warning notification. Numeric-keyed collections are accepted through `ohdearapp/health-check-results`.

Cron task protocol values are agreed but **UNVERIFIED against real Oh Dear data**: neither real account has a cron check. Before the first observation the protocol permits null/pending; the current non-nullable storage uses `pending`. Store `pingFinished`, `pingFailed` and `pingMissed` in the addon's single backed enum, separate from aggregate severity. A late finish within grace is `pingFinished` with warning severity. `starting` preserves the prior value. Keep the enum TODO until real account data can verify these values. `latest_result_label` and `latest_result_label_color` come from our own EN/DE i18n, not assumed Oh Dear account output.

Meaningful cron events include new failure reports while already failed: coalesce the newest failure message/count between evaluations, retain every ping, and do not repeat the same expired-deadline alert or stream lateness deltas. Other addon event identities follow their documented change policy above.

Component CRUD is not a new addon contract. Core SitePolicy/CheckPolicy authorize resolved parents; addon routes call Gate::authorize before using scalar parent/component IDs. API endpoints must verify check type, component ownership and client access before create/update/sync/snooze. Those endpoints belong to the API layer, not the execution engine.

Certificate handshakes and native WHOIS sockets use the same `TargetAddressPolicy` classification and metadata list as HTTP before connecting. The approved numeric destination is used for the socket; TLS peer-name and SNI verification still use the configured hostname. Both certificate handshakes reuse the same resolution. Certificate fetches receive the configured `siteHost`: private addresses are allowed only when the TLS hostname equals it. Foreign-host TLS diagnostics are public-only. WHOIS registry and referral servers are always public-only. Link-local, known metadata and translation/tunnel destinations are always refused. TLS transport uses a fixed enforced 10-second cap under the certificate check's 30-second timeout; CertificateFetcher has no deadline argument. It cannot adapt to a shorter remaining deadline. DNS/domain/Lighthouse adapters also enforce their declared transport budgets. HTTP consumers use the remaining context deadline. Raw unverified PEM capture is not trust validation, and must never disable HTTPS verification in uptime/performance/Lighthouse clients. CertificateFetcher returns the native verify_peer + verify_peer_name handshake verdict; it alone decides validity. A separate unverified capture supplies display-only PEM. Display parsing is capped at 20 certificates; an oversized display chain does not override native verification. System roots remain in OpenSSL's system capath; an operator CA is one PEM file (possibly several certificates), configured as certificate_health.ca_file and loaded as cafile. No operator capath option or own trust/hostname matching exists.
