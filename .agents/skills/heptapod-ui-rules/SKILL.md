# Heptapod UI rules

Add a new pattern to this skill before implementing it. Reuse shared components; do not invent per-page layout variants. Translate all copy through `lang/en/*.json` and `lang/de/*.json`. Use formal Sie in German; keep button labels as infinitives.

## Copy

- One word per concept, in EN and DE. State words (badges, filters, mail subject tags, counts) use the glossary word exactly; prose may inflect it ("ist ausgefallen", "wieder erreichbar").

| Concept | EN | DE |
|---|---|---|
| Uptime outage (state) | Down | Ausgefallen (prose: ist ausgefallen; noun: Ausfall) |
| Uptime OK (state) | Up | Erreichbar (prose: wieder erreichbar) |
| Check result failed | Failed | Fehlgeschlagen |
| Failure (notification category) | Failure / failures | Fehlgeschlagen / fehlgeschlagene Prüfungen (grid, mail footer: `recipient_settings.category.failure.*`) |
| Recovery alert (notification category, mail badge and subject tag) | Recovery / Recovered | Entwarnung ("[Entwarnung]", plural Entwarnungen); "Behoben" only for a resolved incident |
| We could not check | Check error | Prüffehler |
| Warning | Warning | Warnung |
| Uptime (the check and its numbers) | Uptime | Erreichbarkeit |
| Incident | Incident | Störung |
| Check (the thing that runs) | Check | Prüfung |
| Owner (role) | Owner | Inhaber |
| Backup | Backup | Sicherung ("Updates & Sicherungen") |
| Queue worker | Worker | Hintergrundprozess (product names such as Horizon stay as they are) |
| Coding agent | Coding agent | KI-Agent |
| Run one check | Run check | Prüfung starten |

- `scripts/check-translations.php` fails a DE value that says "nicht erreichbar" for an EN "down" key, "Verfügbarkeit"/"Uptime" for an EN "uptime" key, "Check" for an EN "check" key, "Eigentümer" for an EN "owner" key, "Backup" for an EN "backup" key, "Worker" for an EN "worker" key or "Agents"/"Coding-Agent" for an EN "agent" key. Technical endpoints ("Health endpoint unreachable") keep "nicht erreichbar": they are not the Down state.
- One label per destination, in copy too: a catalog value whose EN text names a nav destination (a `title` in `resources/js/lib/navigation.ts`, e.g. "Open System health", "Settings · Routing") uses that destination's DE nav label ("Systemzustand öffnen", "Einstellungen · Routing"). `scripts/check-translations.php` matches the destination phrase (the nav title as written, or a named alias such as "Notification routing" / "routing rules" for Routing) and fails a DE value without a word starting with the nav label; the named exception is "Import" (the nav label is the verb "Importieren", prose names the operation).
- Page, section (FormSection) and sheet (SheetForm) descriptions are one sentence. Anything more goes to the `detail` prop, which renders `InfoTooltip` (`resources/js/components/info-tooltip.tsx`: a 16 px info button labelled "More information" whose shared tooltip holds the detail); a standalone helper paragraph keeps its first sentence and puts the rest in an `InfoTooltip` after it. A tooltip holds background detail only, never something the user needs to act (the next step, the recovery, a required choice) or a consequence of an action (what saving, deleting or refreshing changes or stops); those stay in the visible sentence, shortened if needed. Counts in copy are plural-aware (`_one`/`_other` keys with `count` and `formattedCount`; Laravel `trans_choice` on the server). `scripts/check-translations.php` fails a multi-sentence PageHeader/FormSection/SheetForm description, a standalone helper paragraph (`<p>` or AlertDescription holding one `t()` call, without `role=`) with three sentences or with two once the EN text runs past 120 characters, and an EN count before a plural noun without `_one`/`_other` keys or a "one|many" form (exceptions are named in the script with the reason).
- Gender-fair German: role names are fixed terms and appear as labels (badges, selects: "Inhaber", "Admin", "Mitglied") or as "die Rolle Inhaber". Prose about people uses neutral or verbal wording ("wer die Rolle Admin hat", "Personen mit der Rolle Inhaber", "das Team", "Konto", "Adresse"), never a generic-masculine plural such as "Administratoren", "Inhaber" (as a group), "Benutzer" or "Empfänger". `scripts/check-translations.php` rejects those nouns in DE values outside "Rolle …"; named exceptions: "SMTP-Benutzername" and the Pushover "Benutzerschlüssel" (fixed field names).
- No developer jargon in UI copy. API abilities render through `TokenAbilities` (human chip, raw scope such as `checks:read` in the tooltip); queues and services on System health show a human name with the technical name (`redis:checks-fast`, `gotenberg`) in the tooltip. Never ask the user to type UTC: date entry uses the account or form timezone (the Routing simulator's At uses the account timezone and sends its UTC instant through `zonedInstant`); `scripts/check-ui-primitives.php` rejects a DateTimeField/TimeField with `timezone="UTC"`. `scripts/check-translations.php` fails a catalog value that contains a raw API scope or `agent-read`.

## Foundation

- Use Geist for UI text and Geist Mono for numbers, timestamps, URLs, IDs and evidence. Sizes come only from the named type tokens in `resources/css/app.css`. The heading/value tokens and `text-sm`/`text-xs` also set a line height (and weight/tracking where listed); `text-cell`, `text-label`, `text-micro` and `text-mark` set the size only and inherit the surrounding line height, so they stay inside rows, badges and controls that own their height:

| Token | Size | Use |
|---|---|---|
| `text-page-title` | 26 px / 550, line height 1.15, tracking −0.025em | The page h1 (PageHeader, auth and error pages) |
| `text-headline` | 20 px / 550, line height 1.3, tracking −0.015em | Level-2 PageHeader (check tabs), the Sites health sentence |
| `text-stat` | 20 px, line height 1.25 | KPI values (StatTile), with `font-mono tabular-nums` |
| `text-section` | 14 px / 550, line height 20 px | Section, card, sheet, dialog and empty-state titles (SectionHeading, CardTitle, SheetTitle, DialogTitle, EmptyTitle) |
| `text-sm` | 13.5 px, Tailwind's ratio line height 1.25/0.875 (≈ 19.3 px) | Body text |
| `text-cell` | 13 px, inherits | Table cells, controls (Button, Input, Select, tabs), dense fact lists |
| `text-xs` | 12 px, Tailwind's ratio line height 1/0.75 (16 px) | Meta and helper text |
| `text-label` | 11.5 px, inherits | Table headers, group labels, badges (label weight 450) |
| `text-micro` | 10 px, inherits (callers set `leading-none`) | Pins and markers inside illustrations |
| `text-mark` | 9 px, inherits | Letters inside 20–24 px avatar tiles |

  Off-scale sizes round to the nearest token, not a new one (decision L6, 2026-10-27): the six former 12.5/11/8 px sites became 13/11.5/9 px (segmented control Toggle 12.5 → `text-cell`; members avatar initials, the two DateTimeField labels and the passkey authenticator badge 11 → `text-label`; the design-preview ClientMark letter 8 → `text-mark`). A genuinely new size goes into this table first.
  Never `text-[Npx]`, and never the Tailwind defaults `text-base`/`text-lg`/`text-xl`…; only field primitives in `components/ui/` keep `text-base` below md (16 px stops iOS zoom on focus). Labels use sentence case: no `uppercase` tracking labels. `cn` (`resources/js/lib/utils.ts`) knows the token names so a token and a text colour merge correctly. `scripts/check-ui-primitives.php` rejects arbitrary sizes, off-scale defaults outside `components/ui/` and `uppercase` in TSX classes.
- KPI values use `StatTile` (`resources/js/components/stat-tile.tsx`): SectionHeading label, `text-stat` mono tabular value, optional 12 px muted meta. `bordered` gives a standalone tile its panel (System health); inside a card or form section it stays bare (client summary).
- Buttons, search inputs, segmented controls, badges and run bars are pills. Full-bleed incident banners stay rectangular; a page may use a pill only after placing the banner inside the page container. Panels and overlays use a 10 px radius; form inputs, menu items and nav items use 7 px. Preserve page composition and spacing.
- Status uses colour, shape and a translated word. Reuse StatusDot / StatusBadge: OK open ring; Warning half-filled ring; Failed disc; Down disc with pulsing halo; Check error slashed ring; Pending dotted ring; Paused barred ring; Maintenance centre-point ring; Off dash; Running sweeping arc. Motion is static under reduced motion. Dense check strips use 11 px shapes and a 4 px OK centre point. Unconfigured slots keep a dashed, faint empty cell distinct from Off. Information events use the centre-point info ring. System-health failures use the Check error shape with their own accessible label, never the uptime Down halo. Do not change site/client avatar styling in foundation work.

- Status chips use `StatusBadge`; compact status marks use `StatusDot`. Keep domain-specific translated labels, but map them to the shared semantic shape. System-health failures use `check-error`, never the uptime-only `down` halo. Tags, roles, counts and other metadata stay neutral badges.

## Section headings

Use `SectionHeading` for section titles and KPI labels: the `text-section` token (Geist 14 px, weight 550, 20 px line height). CardTitle, SheetTitle, DialogTitle and EmptyTitle use the same token; FormSection uses SectionHeading. Three heading sizes exist and no others: page h1 (`text-page-title`), headline (`text-headline`), section (`text-section`). Preserve the heading level, labelled-region ID and caller layout; callers must not override typography. Page/episode titles stay in PageHeader; metric values, timeline date dividers and invisible semantic headings are not section-title variants.

## Dates and durations

Date and time entry uses the branded `DateTimeField` / `TimeField` (`resources/js/components/ui/date-time-field.tsx`) for every date or time input: 24-hour `HH:MM` keyboard entry, a localized calendar popover, and the form's timezone shown as a suffix chip. The chip never truncates: it shows the full IANA zone ("Europe/Berlin") whenever it fits beside the value or placeholder, otherwise the city ("Berlin", underscores as spaces), and the input reserves the chip's measured width. Never use `type=date|time|datetime-local|month|week`; submitted values keep the former native string formats. `scripts/check-ui-primitives.php` rejects those `type=` values outside the primitive. Weeks start on Monday everywhere (calendar grid and weekday lists; stored weekday values keep their existing numbering). Unparsable typed input stays visible, is marked invalid and is reported through the caller's `InputError`; a submit never sends the previous value silently.

Use `AbsoluteTime` for standalone absolute dates and timestamps: Geist Mono, a localized medium date and a 24-hour clock to minutes, with the full timestamp and seconds in its shared tooltip. Its clock/date-only modes cover calendar rows without creating page-local formats. `useFormat.timestamp`, `time`, `calendarDate` and `exact` share the presets in `lib/date-time.ts`; string interpolation uses those same presets and puts the exact value on the surrounding fact. Client-language previews use the same presets with the draft locale and timezone.

Seconds are visible only when they distinguish recorded events: Runs attempt timestamps, incident/activity event clocks, the design incident timeline, and sub-two-minute check-history ranges. Use the named `eventTime`/`eventTimestamp` presets for those clocks. Calendar month/day grouping, chart axes, datetime-local input values and fixed-format exports keep their purpose-specific formats. Tooltip contents may show exact seconds. Relative/since labels keep MonitoringTime and its exact tooltip. Translated presentation prose uses the shared minute format. PresentationChanges, ResultSummary and the check-detail PageHeader expose those same instants through a shared exact-time TooltipHint; PageHeader's optional titleTooltip carries that precision without changing the headline.

Future scheduled instants (next run/due, maintenance boundaries, resume and snooze-until) use `AbsoluteTime`, including the date and 24-hour clock across day boundaries. Embedded prose uses `useFormat.timestamp` with the exact time on its enclosing fact. Past last-seen facts keep `MonitoringTime`.

Use the one shared two-unit `useFormat.duration` for elapsed time; never decompose it at callers. Table cells use `useFormat.compactDuration` (largest unit only: "26m", "26 Min.") with the two-unit `duration` in a TooltipHint, so a German duration never widens a table column.

Times in one column are one kind. A column of past instants (Incidents Started, Runs, Maintenance) uses `AbsoluteTime` in every row; MonitoringTime's relative label ("4 min. ago", which turns into "Oct 26" after midnight) is only for a single last-seen fact. The Sites attention band "When" column uses MonitoringTime `since` for every row ("Since 21:56" / "Checked 22:22", the date once the day changes). Response latency remains `responseTime`/`milliseconds`, not an episode duration.

## Tooltips

Use the shared Radix Tooltip primitive for hover and keyboard descriptions. Tooltips keep the same dark surface in both themes: tooltip surface, hairline, bone subject and muted facts tokens; Geist Mono 12 px / 17 px, 6 px radius, compact padding. Structured content uses `TooltipDetails`: subject, facts, a status-coloured status line, then an optional neutral action hint. Colour only a line that states status; Ice belongs to the mark, never the hint. Keep a gap from the trigger, allow collision handling, support Escape and `aria-describedby`, and enter with the `motion-popover` recipe (160 ms; instant for Radix `instant-open` and reduced motion). Chart adapters reuse `TooltipPanel` and `TooltipDetails`, not a separate panel style. Bound their width to the plot, keep X plot-clamped, and let Y leave the plot with a 10 px gap; choose above/below from Recharts' active coordinate and the viewport half. Check strips, retained task-day strips and chart history marks each have one tab stop per strip/chart with Left/Right navigation between named slots. Uptime tooltip placement follows the selected day's measured element on hover and keyboard input, including after resize. Plain labels use TooltipContent without extra structure.

Never a native `title` tooltip (delayed, unstyled, not keyboard reachable). `TruncatedText` (`resources/js/components/truncated-text.tsx`) wraps a `truncate`/`line-clamp` element (or one whose `data-truncate` descendant clips, such as the text span inside TextLink/EntityLink) and opens the shared tooltip with the full text only while the text is cut off; `TooltipHint` always shows a supplementary value such as an exact timestamp (AbsoluteTime, "Observed at" lines), the exact duration behind a compact one, or the URL behind an icon link. TextLink/TextLinkButton `truncate` and `title`, EntityLink and AbsoluteTime use them internally. Every tooltip-only value is reachable without a mouse:
- Screen readers: TooltipHint renders its value as visually hidden text after the element ("26m (26m 14s)"); truncated text keeps its full text in the DOM.
- Keyboard in list rows: no new tab stops. `ListRow` and `TableRow` (or `RowHints` around a linked card) collect their hints; when the row's link or button gets keyboard focus (not after a pointer press), one combined tooltip at that element lists the row's values in column order with their column labels ("Started: … · Duration: …"; pass `label`, AbsoluteTime's `label` for time columns). Cut-off texts join only while cut off. Escape, blur, scroll and resize close it. Mouse hover keeps each cell's own tooltip.
- Keyboard outside rows: a hint whose element is not a link or button becomes one tab stop (`tabIndex=0`, the shared 2 px ring via `[data-hint-focus]`) while it has something to show; fitting text gets no tab stop. A link or button child opens its tooltip on focus as it is.
- One `TooltipProvider` at the app root (`app.tsx`, `delayDuration` 0, shared skip-delay, `disableHoverableContent`); components never mount their own. Exactly one tooltip is visible at a time: moving the pointer straight from one trigger to an adjacent one closes the first and opens the second at once. Tooltip content is never interactive (no links or buttons inside), so it is not hoverable. Vitest gets the same provider through `vitest.setup.ts`.
`scripts/check-ui-primitives.php` rejects `title=` on DOM elements and on `Link`/`Button`/`Badge`, and a `TooltipProvider` outside the app root; named exceptions: `<iframe>` (its accessible frame name) and `<abbr>`.

## View identity

Every primary view states the one question it answers. Layout, ordering, density and liveness follow from that question; shared components do not make every view the same table.

| View | Question | Character |
|---|---|---|
| Websites | Is everything OK, and what needs me? | Calm portfolio overview; attention first. |
| Site overview | Is this site OK, and what needs me? | Attention first, one row per cause; a healthy site has no attention section (the header states it); then the 30-day record and what is coming. |
| Incidents | What broke, when, for how long, is it still going? | Chronological episodes; duration bars; open first. The status filter defaults to Open (a URL without a status shows open incidents; Resolved and All are filters that Clear filters resets to Open). |
| Incident detail | Everything about THIS episode, on one page. | Current evidence and one complete episode timeline. |
| Upcoming | What expires or happens in the coming weeks? | Calm calendar grouped by week/month. |
| Activity | What changed? | Live change feed; newest first; flapping collapsed. |
| Runs | What is the system doing right now? | Live board with three columns, Queued → Running → Finished; stable history below. |
| Check detail | How is this check doing over time, and how is it configured? | Trend, run history and configuration. |

Runs is the live-update exception: engine transitions apply immediately on the board, not in the server-paginated history. Hold structural updates behind “N new changes” while the user reads history, expands evidence or opens a listbox, menu or dialog; apply on click or on returning to the live zone. Upcoming applies live refreshes silently, without a pending-changes prompt or reserved slot. Other views keep the buffered-change rule. Motion marks only state transitions and respects reduced motion.

A closed control retaining keyboard focus never buffers live transitions.

The Runs board has three columns: Queued, Running and Finished. Each run is a card with the site avatar, site name, check type and a phase detail: the queue position in Queued; the run bar, progress and the requesting person for manual runs in Running; the result ring, the stored headline and the duration in Finished. A card opens the check. When a run changes phase, its card moves to the next column; new cards fade in and cards that leave fade out. A card already on the board stays at least 0.4 s in Queued and 1.2 s in Running before it moves on, so a run that finished between two reloads still passes through Running; each card has its own clock, so a burst queues its moves and drops none, and the Finished card shows the real result and duration (`useLiveRunBoard`). A card first seen in a later column appears there at once. With reduced motion or a hidden tab there is no dwell; on returning to the tab the board shows the real state at once (a run that finished meanwhile is already in Finished). With reduced motion, cards change place without movement, and nothing moves while the tab is hidden; the board catches up when the tab is visible again. Unreported progress uses a static striped bar, never a guessed fraction.

Queued shows the first 20 runs in queue order and then the number of further queued runs ("and 12 more queued"). Running shows every running run. Finished shows the newest 8 results of the last 24 hours, then a "Show attempt history" link to the history below, which holds the rest. On desktop the three columns are equal-height tinted lanes with a shared minimum height of six cards (36rem); the tallest lane sets the height of all three. On screens up to 640 px wide, segmented tabs (Queued · Running · Finished, each with its count) show one column at a time; a card that leaves the visible tab slides out and the count of its new tab grows briefly. The page filter (client, check type, state) applies to the board and to the history; the history adds only its time range and the same-result toggle. Changes apply live, except while you read the history or a menu is open: then they wait behind "N new changes". Runs uses the shared PageHeader and its description line for the view question. A small Live status, then Reconnecting and a delayed Reload action when the connection drops, stays above the board; the app shell shows "Reconnecting · showing data from …".

## Pages

Apply these page patterns to monitoring and settings screens rendered in AppLayout. Auth flows, including login, password confirmation and email verification, use AuthLayout and remain a separate pattern. Auth status messages use Alert tone info; fields pass aria-invalid with InputError; loaders use Spinner. Every auth form (login, forgot/reset/confirm password, two-factor, invitation) names each field's InputError id in `aria-describedby` and uses one field rhythm (label, 6 px, control; 22 px between fields); the status Alert sits above the form. Standalone error pages reuse AuthLayout's centered `max-w-sm`, spacing and typography in Blade; the recovery link carries the classes of Button variant default (32 px desktop / 40 px mobile, 13 px label, the shared 2 px ring), with the static AppLogo lockup (`hp-brand`, the same H segments and `hp-word`) and localized status/title/description. Honor the explicit dark appearance cookie on the document root. They must render without JavaScript, user queries or instance settings, including during database failures. Keep Laravel's debug renderer for 500 responses when `app.debug` is enabled. Guest setup/invitations, the local guest component catalog header and design-only branches are outside this rollout.

- Wrap AppLayout content in `PageContainer` (`resources/js/components/page-container.tsx`): centered `max-w-7xl`, `p-4 md:p-6`. Align settings layouts to the same outer edge.
- Use `PageHeader` (`resources/js/components/page-header.tsx`) on AppLayout pages: one h1, Geist 26 px, weight 550, tracking −0.025em, line-height 1.15. Supply an optional count badge and exactly one short, useful muted description line (up to two lines on mobile). Put actions right on desktop and below the title on mobile. Use the optional `leading` slot for an identity mark before the title. Keep contact details and other identity metadata in its shared `metadata` / `meta` slots, not separate local header paragraphs. Existing `metadata` callers use `flex flex-wrap items-center gap-2 text-sm text-muted-foreground`; migrated detail headers use `meta` below the title. PageHeader owns the `trail`/`meta` wrappers and the optional `titleAction` slot (e.g. the site URL icon beside the title); callers pass nodes only. Never put Cancel beside the title.
- App shell: no desktop top bar. Only the active sidebar item names the section. Put the existing command-palette search field under the sidebar wordmark; collapsed sidebars use its icon button. The keyboard shortcuts help is a ghost icon action in the sidebar footer beside Settings (stacked below it when collapsed, hidden in the mobile drawer), never a top-bar or floating button. Mobile uses a 52 px bar with menu, wordmark and search, and the drawer includes the same sidebar search field. Show connection state only when the stream is lost, in a 32 px warning strip above the page with the last-data time. Detail context belongs in the optional PageHeader `trail` above the title, with linked client/site names as text only; the optional `meta` below the title holds status and supporting facts without repeating the trail or title.
- A manual refresh is the PageHeader secondary action "Refresh" (icon, outline): pass `refresh={{ onRefresh, refreshing, disabled }}`; PageHeader renders it before the page's other actions and shows "Refreshing…" while busy. Never a floating, inline or under-table refresh button, and no per-page label ("Refresh list", "Refresh roster"). `scripts/check-ui-primitives.php` rejects `Refresh…` labels outside PageHeader; login's "Refresh session" (CSRF recovery, not a data reload) is the named exception.
- Detail header actions use PageHeader `primaryAction` and `secondaryActions`: below 768 px, show the one primary action and a translated More actions overflow menu; at 768 px and above, cap the actions at 60% of the header width and allow them to wrap so the title stays readable. Use `PageHeaderAction` for secondary button/link triggers so the shared menu owns keyboard navigation without duplicating each action's state. Dialogs and async action errors stay mounted when the menu closes. Incident episode headers and site headers use the shared always-overflow option at every width (one primary, the rest in More actions). Incident episodes: Run check is primary when authorized and available. Site headers (overview, check tabs, site settings): Run all checks… is primary when authorized and available; then every secondary action (Maintenance, Pause site) goes to More actions, even when only one remains (`overflowSecondary="always"`). Without a primary (no runnable check) the secondary actions stay plain buttons. Incident episodes and every other header with `overflowSecondary`: a single secondary action stays a plain button; More actions appears only for two or more. Never leave only a More menu without a visible primary action. The shared overflow supports controlled opening so #snooze can open the existing reminder choices.

## View identity

- Each primary view answers one question. Its ordering, density and liveness follow that question.
- Upcoming answers “What expires or happens in the coming weeks?” Use a calm agenda grouped into this week, next week, then calendar months. Within each section, group items by date. Show the absolute date and relative calendar-day date once in the shared ListHeader, then two-line linked ListRows (site + client, kind + detail). Subscribe through the shared live hook and apply incoming items silently with no animation or pending-changes slot. Refresh items and the calendar-day reference together.
- Activity answers “What changed?” Use a newest-first feed with check and site identity. Keep foreign live changes behind the shared PendingChanges control in FilterBar's existing toolbar row via its status slot, visible even when mobile filters are collapsed. Animate only newly accepted rows, and disable that motion for prefers-reduced-motion. Server-collapsed alternating state changes with gaps below two hours show the two states, event count, absolute time span and current end state; expand to a separately paginated event list.

## Forms

- Use `FormSection` (`resources/js/components/form-section.tsx`): title and description left, fields right. Stack below 768 px of available section width so narrow settings content behaves like mobile.
- One save pattern for every form: one page, one form, one bar.
  1. An inline field is a draft. Every input, toggle, select or dropzone shown directly on a page belongs to that page's one form; nothing applies until Save.
  2. One bar, docked at the bottom. `FormActions` (same file) portals into `FormActionsDock`, the one slot at the end of `main` in the app shell (`app-sidebar-layout.tsx`): sticky to the viewport bottom, full content width, inner row aligned to the PageContainer `max-w-7xl` + `px-4 md:px-6`, top border, background with a slight blur. It sits in flow, so scrolled to the end it never covers the last content, and it is the last tab stop in `main` on every page. Always visible while the page has a form: status left, Discard/Cancel + the primary action right. Dirty-gated forms pass `FormSaveStatus` (No unsaved changes / warning StatusDot + Unsaved changes / Saving…) and keep Discard and the primary disabled until a field changes, Security included; Add site shows a live summary of what will be created there instead (`example.com · Client · 8 checks will run`, "2 fields need attention" after a refused submit, Saving…) and keeps Add site enabled. One row at 390 px: the status truncates, the buttons never wrap under it. The bar renders outside its `<form>`, so the submit button carries `form="<form id>"`; without it Save does nothing. FormActions takes no `className`; it throws outside the dock. SheetForm and Dialog footers keep the same edge: the commit button is always at the bottom.
  3. Everything else is a button that names its effect: "Change…" or "Edit note" opens a SheetForm (own footer), delete/archive open a ConfirmDialog, one-shot actions (Refresh icon, Retry) act at once. No inline control on a page with a bar applies immediately; no per-section or per-card Save buttons.
  4. No inline fields, no bar: pages that work only through sheets and dialogs (members, API tokens, maintenance, channel lists, incident notes) have none.
  5. Never a second bar on a page: when two independent forms share a page, one moves into a sheet.
  The one named exception is the Oh Dear import: its token field feeds the one-shot "Show plan" action (read-only, nothing is imported), and the bar with Start import appears once a plan exists.
- A FormSection may group its fields and a supporting panel in a nested two-column grid at lg: flexible fields on the left, a 16rem panel on the right. Stack the panel after the fields on mobile; keep both inside the section's field column.
- Discard/Cancel/Back in FormActions, SheetForm and Dialog footers use the shared secondary action (`FormSecondaryAction`, outline) next to a default primary action; never pick a variant per page. Keep action behaviour and disabled states unchanged.
- Focus return: dialogs and sheets open from state, so `DialogContent` (and with it ConfirmDialog and the command palette) and `SheetForm` record the opener through `useReturnFocusToOpener` (`resources/js/lib/focus-return.ts`) and focus it on close: a menu item's opener is its menu trigger; an opener that closed as the overlay opened (a palette command, a create sheet handing over to a shown-once dialog) falls back to the last control focused outside every overlay. When the opener is gone on close, focus goes to a stable replacement: the same-named control in the opener's region, else that region's More actions trigger (a card toolbar folded below 640 px), else the region heading, else `main`. A caller whose opener is replaced while open (Security's Enable 2FA becomes Continue setup) passes `onCloseAutoFocus` and focuses its current action. A dialog closed while the app leaves the page (a GET visit to another path in flight, or Inertia `navigate` to another path or component) leaves focus to the new page, and the caller's own `onCloseAutoFocus` is skipped too (the palette must not refocus Search).
