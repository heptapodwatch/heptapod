# Domain check

The check polls every 24 hours. RDAP timestamps are exact and stored in UTC. WHOIS dates are calendar dates only (`date_precision: day`), with up to one day of UTC uncertainty because Whoeasy 2.0.3 discards timezone offsets. Expiry thresholds use that calendar day; no WHOIS time-of-day precision is claimed.

RDAP uses IANA bootstrap plus registry overrides for DE, CH, IO and US. AT and EU use WHOIS directly. WHOIS uses bounded native TCP reads (256 KiB, 10-second read budget); referrals are disabled and only package registry servers are contacted. HTTP-WHOIS registries, including VN, are unavailable with reason `registry only offers HTTP WHOIS (unsupported)`. DENIC's missing expiry is explicitly unsupported, not expired. Other missing or denied lookups are errors and do not replace the accepted baseline. Dangerous RDAP statuses remain authoritative even without an expiry date.

Every response key and scalar value, including numeric keys and values, is compared as a string against configured secrets and crawler-header values, case-insensitively. A match rejects the observation with `lookup response contained a configured secret value`: no raw evidence, staging or addon events; the accepted baseline remains. The same check protects projected evidence and previous snapshots before event construction.

RDAP and IANA bootstrap use the core HTTP seam with 256 KiB wire and decoded limits, a 10-second ceiling and the engine deadline. Untrusted redirects allow up to three hops with target validation and address pinning. HTTP availability failures and malformed registration/bootstrap data use WHOIS fallback. Limit, invalid-request, redirect-policy and private-target failures are unavailable observations; they do not update the accepted baseline.

DNS and domain checks use core's `resources/public_suffix_list.dat` through `Heptapod\Contracts\PublicSuffixList`. The bundled list is from https://publicsuffix.org/list/public_suffix_list.dat, version `2026-09-30_20-56-07_UTC`, retrieved on 2026-10-01. Mozilla and contributors publish it under MPL-2.0: https://mozilla.org/MPL/2.0/. Attribution is retained in the core data file and `resources/README.md`. Maintainers refresh it in a source checkout before building a release image; instructions are in core's `docs/deploy/operations.md`. Parsing uses `jeremykendall/php-domain-parser`, not local suffix rules.
