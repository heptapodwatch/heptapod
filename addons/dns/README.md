# DNS monitoring

The URL hostname is always monitored. `monitor_main_domain` adds its registrable domain (Public Suffix List); `extra_cnames` adds complete hostnames with the same watched types. The default interval is one hour.

- Types: A, AAAA, CNAME, MX, TXT, NS and CAA, minus `ignored_record_types`.
- Ignored types are case-insensitive, normalized to uppercase and distinct. The allowlist and list limit follow the installed `spatie/dns` package's supported types, not an assumed complete Oh Dear enum. SOA, SRV and PTR are accepted but have no effect because they are not polled anyway. Unknown names fail validation.
- Comparison uses a sorted, deduplicated set. TTL and answer order do not count as changes. A/AAAA change detection uses the union of all authoritative answers, including when synchronization is disabled; rotating geo/anycast answers between nameservers do not create changes. Hostnames and domain targets are case-insensitive and ignore the trailing root dot; IPv6 uses canonical binary identity. TXT content, MX priority and CAA fields are significant.
- Empty optional types establish a valid baseline. A type becomes expected on its first non-empty accepted observation. If it becomes empty, the check stays failed until records return, `ResetDnsBaseline(checkId)` is called, an accepted observation ignores that type, or a user accepts the observation as normal. Ignoring a type clears its expectation. A reset takes effect from the next run; an already running check finishes with its original result and may emit its already-computed change event. Its pre-reset observation cannot restore the baseline or expectations. The next accepted observation creates fresh initial history without a change event.
- A/AAAA/CNAME are always queried for liveness, even when ignored. A hostname with none of these fails. Nameserver synchronization, when enabled, compares the nearest enclosing zone's SOA serial and the watched stable types NS/MX/TXT/CAA/CNAME across its authoritative nameservers. A/AAAA are excluded from synchronization because geo/anycast providers legitimately serve different addresses. Only NS records owned by the queried zone are eligible; a cross-zone CNAME does not select the target zone's servers. Without an established authority, synchronization is not assessed.
- Authorities are discovered before collecting records. A recursive timeout or SERVFAIL during NS discovery retries at the enclosing zone. Direct queries require the authoritative-answer (AA) flag; a parent's referral is not an empty authoritative observation. If discovery finds no authority, the baseline is unchanged and no record-change event is emitted; recursive data is used only for liveness. Non-empty recursive liveness warns that authorities are unreachable. Empty recursive liveness fails when discovery completed without transport failure; after discovery timeout/SERVFAIL it errors because the outage is inconclusive. A failed recursive collection errors too. These rules apply with synchronization enabled or disabled. AA-marked negative answers from established authorities remain valid observations. A recursive timeout or SERVFAIL during record collection uses a complete authoritative observation instead; partial replies are discarded. Run evidence retains an informational `dns.resolver_unavailable` diagnostic with `timeout`/`servfail` reason (EN/DE). With every authority answering completely, this is a healthy result, not a warning or notification.
- An unavailable authoritative nameserver produces a warning issue with its name and `timeout`/`servfail` reason if another nameserver answers completely. Synchronization and liveness use only complete observations. Any authoritative failure preserves the entire accepted baseline and suppresses record-change events, including recovery additions. If every authority fails but the recursive observation completes, the result warns, skips synchronization, and uses the recursive data only for liveness. Missing records or failed liveness still fail the check. If both paths fail, the run errors.
- Only timeout and typed SERVFAIL failures are recoverable. REFUSED and other resolver statuses, malformed/truncated/oversized answers, process failures, and overall deadline exhaustion are engine errors. They never replace the accepted baseline or create removed-record events. Decoded dig stdout and stderr share a 128 KiB read-time cap; overflow stops the process before parsing or staging. Raw process/parser messages are excluded from diagnostics.
- The first accepted observation creates an initial history item without a change event. Later items are created only when records, issues or authoritative nameservers change. Raw observations are retained separately for run provenance; the accepted baseline survives pruning.
- `dns.records_changed` carries per-type added/removed records. Public TXT values remain visible, capped at 255 characters with `...`. Payloads contain no request headers or configuration secrets. New configured hostnames/types establish their own baseline without a change event. Dedupe combines check ID, accepted predecessor run and full normalized-set identity.

Runtime requires `dig` (`dnsutils` on Debian). Each lookup has one three-second attempt and a five-second process cap; the check has a 120-second deadline. Before each lookup, the remaining budget must cover its process cap. Exhaustion stops the run as an error, without publishing a partial record set. Limits are 20 extra hostnames, 1,000 records per response, 200 display records and 16,000 raw display characters. Larger answers fail rather than silently truncating comparison data.

DNS and domain checks use core's `resources/public_suffix_list.dat` through `Heptapod\Contracts\PublicSuffixList`. The unmodified list was downloaded on 2026-10-01 from https://publicsuffix.org/list/public_suffix_list.dat and is licensed MPL-2.0 (https://mozilla.org/MPL/2.0/). Attribution is preserved in the core data file and `resources/README.md`. Maintainers refresh it in a source checkout before building a release image; instructions are in core's `docs/deploy/operations.md`. Domain parsing uses `jeremykendall/php-domain-parser`; execution performs no PSL download.

Offline tests use official, digest-pinned CoreDNS with the zone files in `tests/Fixtures/zones`. A test-only executable in `tests/Support` exercises the external process boundary for oversized output and unsafe diagnostics; tests restore PATH and environment afterward. Start the fixtures profile and run `vendor/bin/pest addons/dns/tests`. UI and API endpoints are separate work packages. Baseline reset authorization and audit entries belong to those entry points.
