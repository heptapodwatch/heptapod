# Lighthouse

- Polls the site's URL every 24 hours on `checks-browser`. The check timeout is 170 seconds; the HTTP adapter caps service calls at 155 seconds. The browser worker has concurrency 1.
- `device_emulation` accepts `mobile` (default) or `desktop`. `cpu_slowdown_modifier` accepts null or 1–20; omission/null uses 4 for mobile and 1 for desktop.
- `continent` is stored for compatibility. Measurements run from the instance location.
- `notification_settings` is an open, nullable object. Known keys `performance`, `accessibility`, `best_practices`, and `seo` accept nullable integer thresholds from 0–100. Omission or null disables that threshold. Unknown settings are preserved but not used.
- A score strictly below its threshold or a drop of at least 10 points from the previous accepted report warns. A browser error produces an errored run with null metrics, not a score of zero. Valid zero scores remain zero. Missing audit metrics and the removed PWA category remain null.
- Each valid accepted report advances the baseline. Errors and stale attempts cannot advance it. Baseline scores survive raw-report pruning.
- `lighthouse.score_threshold_crossed` emits once per category crossing against the accepted baseline. Both scores use the current threshold, so a settings-only edit does not emit an event. First observations emit no crossing event. Payload version 1 contains `category`, `direction` (`below`/`above`), `previousScore`, `actualScore`, and `notificationThreshold`.
- Headers retain their ordered encrypted settings representation. At execution, check headers override site crawler headers case-insensitively. The Chromium seam receives `{desktop, cpuSlowdownMultiplier, extraHeaders}`, where `extraHeaders` is a header object. The Node service uses Lighthouse's Puppeteer page integration: headers are injected only for the original site origin (scheme, host, effective port), including after redirects. Third-party requests receive none. Service workers are bypassed. Credentials never enter process arguments, logs, or LHR settings.
- Archived LHR JSON preserves object/list identity, including empty objects. Evaluation uses a separate associative parse. `configSettings.extraHeaders` values are replaced with `[redacted]`; every property name and scalar value is checked case-insensitively against configured header secrets, including numeric names and values. Reports are gzip-compressed and base64-encoded for PostgreSQL storage. Metrics, evidence, events, and diagnostics exclude raw LHR data.
- Service calls use core `OutboundHttp`, with 8 MiB wire/decoded limits during transport, no redirects, native TLS, and the current execution deadline. Failures carry static typed diagnostics. Archive traversal delegates all secret matching to core `SecretRedactor`, including its protected-mask handling.
- Detail scores/evidence come from the current accepted physical run, never its comparison baseline. An errored run has no scores; retained baseline scores remain available only for the next comparison.
- With `HEPTAPOD_BROWSER_ENABLED=false`, checks present as unavailable with a translated installation reason in UI/API. They are excluded from scheduling and manual runs, create no observations/incidents/notifications, and resume when enabled. The last run result remains unchanged.
- The Oh Dear importer accepts the declared settings and scheduling keys. Missing/null optional source fields use schema defaults. Unsupported settings are reported, not silently dropped.
- Real service origin-isolation proof is runnable with `docker compose exec app vendor/bin/pest addons/lighthouse/tests/Manual/LighthouseOriginIsolationTest.php --compact` after starting the local Lighthouse service. This opt-in test requires native Chromium and is outside the default suite.
