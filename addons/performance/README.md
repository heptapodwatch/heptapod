# Performance

- Derives observations from accepted, online uptime runs without another HTTP request. Missing timings and failed or errored runs are not samples.
- Both warning branches use the last 60-minute median. The absolute branch exceeds `threshold_in_ms` (default 2000 ms). The displayed average remains the arithmetic mean of the same samples.
- The relative branch requires the current median to exceed `max(baseline p90, baseline median × (1 + change_percentage / 100))` and be at least 200 ms above its median. `change_percentage` defaults to 50% and is labelled “Minimum change from normal”. The baseline contains the same UTC hour from each of the preceding seven days, excluding today. Percentiles use linear interpolation.
- Relative comparisons require at least three current samples, nine baseline samples across three distinct prior days and a positive baseline median. Until then, only the absolute threshold applies.
- Three consecutive elevated evaluations enter Warning. Recovery requires three consecutive evaluations that clear both recovery bands. `recovery_margin_percentage` is an integer from 0 to 20, default 5. The absolute recovery bound is `threshold_in_ms × (1 − margin / 100)`; the relative bound applies the same factor to `max(relative threshold, baseline median + 200 ms)`, preserving the entry rule's equality boundaries. Band values keep Warning and reset recovery progress. Margin 0 preserves the boundaries without a band.
- A speed-up emits one `performance.improved` info event (“Got faster: 2.1 s → 0.31 s (−84%)”). It needs the same samples as the relative branch, a current median below `baseline median × (1 − change_percentage / 100)` and at least 200 ms below the baseline median, on three consecutive evaluations outside a Warning; a recovery evaluation never counts. The event fires on the third evaluation only; it re-arms after three consecutive evaluations that are no longer fast. It never changes the result or touches incidents. Routing puts it in Changes, off by default.
- “What we check” shows the absolute “Recovers below” bound directly under Threshold: 1900 ms with default settings. The relative bound varies with the baseline. Margin changes apply on the next evaluation without resetting confirmation counts.
- Empty current windows return no observation. Zero timings are real samples. One history read combines eight index-bounded windows with `UNION ALL`. Each window has its own limit of 10000 observations; reaching a limit throws rather than returning incomplete history. Overlapping windows are deduplicated by physical run identity.
- Existing stored configurations use the default recovery margin without a migration. The API returns stored setting keys, not implicitly inserted defaults. Oh Dear imports have no recovery-margin field. Config `change_percentage` remains an active threshold; the similarly named run metric reports the observed median increase.
